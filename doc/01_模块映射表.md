# EasyPyADB → Compose Multiplatform 模块映射表

> 目标：将当前 Python + PyQt5 项目迁移到 Compose Multiplatform（仅桌面端）。
> 本文给出"现有 Python 文件 → 目标 CMP 模块/包"的逐文件映射，并标注迁移策略与难点。

---

## 一、目标 CMP 项目整体结构

```
easyadb-cmp/
├── build.gradle.kts                     # 根构建脚本
├── settings.gradle.kts                  # 模块声明
├── gradle/libs.versions.toml            # 版本目录（依赖统一管理）
│
├── core/                                # 纯 Kotlin Multiplatform 业务/数据层（不含 UI）
│   ├── adb/                             # ADB 命令构造、子进程执行、设备发现
│   ├── database/                        # SQLDelight 本地数据库
│   ├── config/                          # XML / INI 配置加载
│   ├── log/                             # 跨平台日志门面
│   ├── device/                          # 设备/包名/进程 领域模型
│   ├── apk/                             # APK 解析（aapt/apksigner 包装）
│   └── util/                            # 通用工具（IP 校验、文件哈希等）
│
├── ui/                                  # Compose Multiplatform 共享 UI 层
│   ├── designsystem/                    # 主题、颜色、字体、图标、通用组件
│   ├── home/                            # 主窗口（左 TreeView + 中 Tab + 底 Tab）
│   ├── devicelist/                      # 设备树 / 命令树面板
│   ├── functions/                       # 中部功能区（动态 UI 模板）
│   ├── console/                         # 应用日志控制台
│   ├── logcat/                          # 实时 logcat 视图
│   ├── mirror/                          # Scrcpy 镜像（独立窗口/嵌入）
│   └── dialogs/                         # 各类对话框
│
├── desktop-app/                         # 桌面应用入口（composeForDesktop）
│   └── src/jvmMain/
│       └── kotlin/com/easyadb/desktop/  # main()、Application 单例、依赖注入装配
│
├── platform/                            # 平台特定实现（expect/actual）
│   ├── desktopMain/                     # JVM 桌面通用实现
│   ├── windowsMain/                     # Windows 专属（Scrcpy 嵌入、wt.exe）
│   ├── macosMain/                       # macOS 专属
│   └── linuxMain/                       # Linux 专属
│
└── res/                                 # 资源文件（图标、XML 模板、INI）
```

**模块依赖方向（重要）**：

```
desktop-app
    ↓ depends on
ui:* (Compose UI)
    ↓ depends on
core:* (业务逻辑)
    ↓ depends on
platform (expect/actual)
```

UI 模块**不能反向调用** desktop-app，业务层**不能依赖** Compose。这是保证后续扩展（如未来上 Android/iOS）时 UI 可复用的前提。

## 二、入口与启动流程

| 当前 Python 文件 | 职责 | 目标 CMP 位置 | 迁移要点 |
|---|---|---|---|
| `EasyADB.py` | 应用入口；设置高 DPI；触发依赖检查；创建 MainWindow；安装异常 hook | `desktop-app/src/jvmMain/kotlin/com/easyadb/desktop/Main.kt` | Compose Desktop 用 `application { Window(...) }`；高 DPI 由 Skia 自动处理，删除手动缩放代码；异常 handler 用 `Thread.setDefaultUncaughtExceptionHandler` |
| `Dependencies.py` → `AndroidDependencies` | 检查 `platform-tools` 是否齐全，缺失则弹窗下载/解压 | `core/adb/.../DependencyChecker.kt` + `platform/.../PlatformToolsDownloader.kt` + `ui/dialogs/DependencyMissingDialog.kt` | 下载逻辑通用化；`adb.exe` 改为按平台选择二进制名（`adb` / `adb.exe`）；`LOCALAPPDATA` 用 `platform/.../AppPaths.kt` 抽象 |
| `Dependencies.py` → `ScrcpyChecker` | 检查 `scrcpy` 是否存在，缺失则后台下载并解压；通过 `pyqtSignal` 通知 UI | `core/adb/.../ScrcpyChecker.kt` + `ui/mirror/.../ScrcpyBootstrap.kt` | 下载用 `kotlinx.coroutines` + `Flow` 替代 QThread + pyqtSignal；用 `StateFlow<ScrcpyState>` 暴露状态 |

## 三、业务/数据层（core/*）

### 3.1 ADB 命令执行（替换 `utils/ADBTools.py` + `utils/CmdExecutor.py`）

| Python 类/函数 | 目标位置 | 迁移策略 |
|---|---|---|
| `ActionCmdParams` | `core/adb/.../model/ActionCmdParams.kt` | 改为 `data class`，`getAdbCMD()` → `fun compose(targetApp, deviceSerial): String`；`{0}` 占位符替换为 Kotlin 模板字符串 |
| `ADBTools.exec_adb_cmd` | `core/adb/.../AdbExecutor.kt` | 用 `ProcessBuilder` 替代 `subprocess.Popen`；返回 `Flow<AdbOutput>` 而非回调 |
| `ADBTools.async_exec_adb_cmd` | `core/adb/.../AdbExecutor.kt#executeAsync` | 用 `suspend` + `Dispatchers.IO`；批量命令用 `flow` 流式输出 |
| `CmdExecutor`（QThread + 超时定时器） | `core/adb/.../AdbExecutor.kt`（合并） | 用 `withTimeout` 替代 QTimer 超时；删除 QThread |
| `LiveLogAdbThread`（实时 logcat 子进程） | `core/adb/.../LogcatStream.kt` | `subprocess.Popen` → `ProcessBuilder.start()`；stdout 逐行读取用 `flow` + `BufferedReader.lineSequence()`；停止用 `Process.destroy()` 替代 `os.kill(SIGINT)` |
| `AsyncAdbThread` | `core/adb/.../AdbExecutor.kt`（合并） | 合并到 `executeAsync` 流式输出 |
| `GetAppListThread` | `core/adb/.../PackageListFetcher.kt` | 同样改为 suspend 函数；解析 `pm list packages -f` 的逻辑可保留 |
| `get_filter_processes` / `process_user_name_check` | `core/adb/.../ProcessListParser.kt` | 正则不变，转为纯 Kotlin 函数 |
| `LiveLogAdbThread.LogCatFilter` | `core/logcat/.../LogcatFilter.kt`（见 §3.5） | 拆出为纯逻辑类，无 Qt 依赖 |

## 八、迁移难度分级

| 难度 | 模块/文件 | 说明 |
|---|---|---|
| **简单（直接对译）** | `core/adb/ActionCmdParams`、`core/util/IpValidator`、`core/device/DeviceInfo`、`core/config/*Config`、`ui/dialogs/*` 中简单对话框、`ui/home/MenuBar` | 逻辑清晰，无 Qt 强耦合 |

## 九、迁移原则小结

1. **配置先迁、UI 后迁**：XML/INI 配置加载是纯逻辑，迁移成本最低，先做能立刻被后续模块复用。
2. **业务层无 Qt**：所有 `core/*` 模块禁止出现 `Q*` 导入，保证未来可上 Android。
3. **着色从 HTML 转 AnnotatedString**：当前 `LogUtils.changeLogColor` 返回 HTML 字符串塞进 `QTextBrowser`，迁移后改为 UI 层根据 `LogEntry.level` 选 `Color` 渲染 `Text`，性能也更好。
4. **轮询 / 子线程统一用 Flow**：`DevicesWatcher`、`LiveLogAdbThread`、`CmdExecutor`、`ScrcpyChecker` 全部收敛为 `Flow` + `StateFlow`。
5. **保留 XML 模板格式**：`menus_ui.xml` / `function_templates.xml` / `cmdConfig.xml` 字段不动，降低用户配置迁移成本。
6. **路径抽象**：所有 `LOCALAPPDATA` / `os.getcwd()` / 反斜杠路径必须走 `platform/.../AppPaths.kt`。
