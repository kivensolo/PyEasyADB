# EasyPyADB → Compose Multiplatform 分阶段迁移计划

> 配套文档：[`01_模块映射表.md`](./01_模块映射表.md)
> 目标平台：**仅桌面端**（Windows / macOS / Linux）
> 范围约束：Scrcpy 嵌入模式降级为「独立窗口模式」优先实现，嵌入模式作为后续增强。

---

## 总体策略

| 维度 | 决策 |
|---|---|
| UI 框架 | Compose Multiplatform（Compose for Desktop） |
| 业务层 | Kotlin Multiplatform（pure KMP），不含 Compose 依赖 |
| 异步模型 | `kotlinx.coroutines` + `Flow` / `StateFlow` |
| 数据库 | SQLDelight（保留原表结构以便迁移老 `easyADB.db`） |
| HTTP | JDK `HttpClient`（不引 Ktor，减少依赖体积） |
| 配置 | XML 模板继续使用（菜单/命令/功能区模板），权限表用 `Map` 常量 |
| 日志 | kotlin-logging + 自实现文件滚动 |
| 构建 | Gradle Kotlin DSL + `libs.versions.toml` 版本目录 |
| 渲染 | Skia（Compose Desktop 默认） |
| 分发 | `jpackage` 生成各平台原生安装包（`.msi` / `.dmg` / `.deb`） |

**核心原则**：业务层 `core/*` 模块**绝对禁止**导入 `androidx.compose.*` 或 `Q*`，所有 UI 关注点收敛到 `ui/*`，平台相关代码走 `expect/actual`。

## P0 — 脚手架搭建（约 0.5 周）

### 目标
- 在仓库内新建 `cmp/` 子目录（或独立新仓库），跑通 Compose Desktop 最小可用工程。
- 三端（Windows / macOS / Linux）启动一个空白窗口。

### 任务清单
- [ ] 初始化 Gradle 多模块项目（Kotlin DSL）
- [ ] 配置 `gradle/libs.versions.toml`：Kotlin、Compose、Coroutines、SQLDelight、kotlin-logging
- [ ] 创建空模块：`core:util`、`desktop-app`
- [ ] `desktop-app` 中写 `Main.kt`，`application { Tray / Window(...) { Text("Hello") } }`
- [ ] 配置 `compose.desktop.application.mainClass`，三端 `./gradlew run`
- [ ] 配置应用图标（`ic_app.ico` 转 `.icns` / `.png`）
- [ ] 接入 `kotlin-logging`，跑通最简单的文件日志输出
- [ ] CI：GitHub Actions 跑 `./gradlew build` 三端编译

### 验收标准
- 在 Windows / macOS / Linux 任一机器 `./gradlew run` 能弹出窗口
- 日志文件出现在 `%LOCALAPPDATA%/EasyADB/logs/`（Windows）或对应平台路径

### 关键决策
- **仓库策略**：建议在现有仓库新建 `cmp/` 子目录而非另起仓库，便于迁移期对照 Python 源码；MVP 完成后再决定是否独立。
- **包名**：`com.easyadb`（com.${reverse-domain} 约定）。

## P1 — Core 层迁移（约 2 周）

> 这是迁移的核心阶段，目标是把所有非 UI 的业务逻辑搬到 `core/*`，能脱离 UI 跑单元测试。

### P1.1 平台抽象层（platform/*）

**对应 Python**：散落在 `settings.py`、`Dependencies.py`、`win32Wrapper.py` 的平台调用。

- [ ] 定义 `expect class AppPaths`：
  - `appDataDir: File`（设备/数据库/工具的存放根目录）
  - `logsDir: File`
  - `tempDir: File`
- [ ] 三端 actual 实现：
  - Windows：`%LOCALAPPDATA%/EasyADB/`
  - macOS：`~/Library/Application Support/EasyADB/`
  - Linux：`$XDG_DATA_HOME/EasyADB/`（fallback `~/.local/share/EasyADB/`）
- [ ] 定义 `expect class ProcessKiller`：跨平台杀子进程
- [ ] 定义 `expect class TerminalOpener`：打开外部终端（替代 `wt.exe` 硬编码）

### P1.2 配置加载（core/config/*）

**对应 Python**：`AppConfigManager.py`、`MainWindow.__loadAdbCmds`、`CenterWindow._setUpUIDynamic`、`MenuActions.setupUi` 中的 XML 解析。

- [ ] `PermissionNameMap.kt`：把 `AppConfig.ini` 的权限翻译表编译为 `Map` 常量（或从 classpath 加载 `.properties`）
- [ ] `MenuConfig.kt` + 解析器：从 `menus_ui.xml` 读取 → `data class MenuEntry`
- [ ] `FunctionTemplate.kt` + 解析器：从 `function_templates.xml` 读取 → `data class Template / TemplateItem / ItemAttr`
- [ ] `CmdConfig.kt` + 解析器：从 `cmdConfig.xml` 读取 → `data class CmdGroup / CmdItem`
- [ ] **单测覆盖**：用现有 XML 文件做 golden test，确保解析结果一致

### P1.3 数据库（core/database/*）

**对应 Python**：`src/DataBase.py`。

- [ ] 引入 SQLDelight，配置 `sqldelight` 扩展
- [ ] 编写 `.sq` 文件：`Device.sq`、`Package.sq`（**保持表结构与字段名与 Python 完全一致**，便于老用户数据迁移）
- [ ] 生成 `DeviceQueries` / `PackageQueries`
- [ ] `DeviceRepository.kt` / `PackageRepository.kt` 封装 DAO
- [ ] 数据库迁移脚本：检测旧 `easyADB.db` 时自动迁移到新位置
- [ ] **单测覆盖**：用内存数据库（`jdbc:sqlite::memory:`）跑全部 CRUD

### P1.4 ADB 命令执行（core/adb/*）

**对应 Python**：`utils/ADBTools.py`、`utils/CmdExecutor.py`。

- [ ] `ActionCmdParams.kt`：data class，含 `compose(targetApp, deviceSerial): String`
- [ ] `AdbExecutor.kt`：
  - `suspend fun execute(cmd: String, timeout: Duration): Result<String>`
  - `fun executeStreaming(cmd: String): Flow<AdbEvent>`（替代 `AsyncAdbThread`）
  - `withTimeout` 替代 `CmdExecutor._onCmdExectuedTimeout`
- [ ] `LogcatStream.kt`：实时 logcat 流（替代 `LiveLogAdbThread`）
- [ ] `PackageListFetcher.kt`：`pm list packages -f` 解析（替代 `GetAppListThread`）
- [ ] `ProcessListParser.kt`：`ps` 输出解析（替代 `get_filter_processes`）
- [ ] `AmCommandBuilder.kt`：拼装 `am start / broadcast` 命令（替代 `CenterWindow.build_am_cmd`）
- [ ] **集成测试**：连真机跑 `adb devices`、`adb shell ps`、`adb shell pm list packages -f`，校验解析

### P1.5 设备监听（core/device/*）

**对应 Python**：`src/DevicesWatcher.py`。

- [ ] `DeviceInfo.kt`：data class，`state: DeviceState` 枚举
- [ ] `DeviceAddress.kt`：封装 `ip:port / emulator-xxxxx / 纯数字名称` 三种形态
- [ ] `DeviceWatcher.kt`：`fun watch(): Flow<List<DeviceInfo>>`，内部 `while(true) { delay(2000); ... }`
- [ ] `SelectedAppRepository.kt`：当前选中包名、当前选中进程的 `StateFlow`（替代 `PackageManager` 单例）

### P1.6 日志系统（core/log/*）

**对应 Python**：`src/logcat/log.py`、`utils/Utils.py::LogUtils`。

- [ ] `LogLevel.kt`：枚举，含 `fromChar('V' / 'D' / ...)` 反查
- [ ] `LogEntry.kt`：data class（timestamp / level / message / source）
- [ ] `LogBus.kt`：`MutableSharedFlow<LogEntry>`，UI 订阅
- [ ] `FileLogger.kt`：基于 `java.util.logging` 或自实现滚动文件 handler（保留 `maxBytes=4MB / backupCount=128`）
- [ ] `Logger.kt`：facade，对外 `info / debug / warn / error / infoWithStamp`，内部把 entry 推到 `LogBus` + 写文件
- [ ] **去除**：`LogUtils.changeLogColor` 的 HTML 字符串返回，改为 UI 层根据 level 取 `Color`

### P1.7 APK 解析（core/apk/*）

**对应 Python**：`utils/Utils.py::FileUtils`。

- [ ] `FileHasher.kt`：MD5 计算
- [ ] `AaptInvoker.kt`：调用 `aapt dump badging / xmltree`，沿用现有正则
- [ ] `ApkSignerInvoker.kt`：调用 `apksigner` 验签
- [ ] `ApkParser.kt`：聚合上述，返回 `data class ApkInfo`
- [ ] 注意：aapt/apksigner 是外部二进制，沿用现有调用方式（不重写解析逻辑）

### P1.8 依赖检查（core/adb/* + platform/*）

**对应 Python**：`Dependencies.py`。

- [ ] `PlatformToolsChecker.kt`：检查 `adb` 是否可用，缺失则用 `HttpClient` 下载 + `zip` 解压
- [ ] `ScrcpyChecker.kt`：同上，**MVP 阶段只下载不嵌入**
- [ ] 下载进度通过 `StateFlow<DownloadState>` 暴露
- [ ] URL 按平台动态拼接（`scrcpy-win64-vX.Y.Z.zip` / `scrcpy-macos-vX.Y.Z.zip` / `scrcpy-linux-vX.Y.Z.zip`）

### P1.9 通用工具（core/util/*）

**对应 Python**：`utils/Tools.py`、`utils/Utils.py`。

- [ ] `IpValidator.kt`：保留正则
- [ ] `TimeFormatter.kt`：基于 `kotlinx-datetime`
- [ ] `Downloader.kt`：JDK `HttpClient` 封装，带进度回调
- [ ] `ZipExtractor.kt`：基于 `java.util.zip`

### P1 验收标准
- `./gradlew :core:adb:test` 全绿
- 在 Kotlin REPL 中能：`AdbExecutor().execute("adb devices")`、`DeviceWatcher().watch().collect { println(it) }`
- 老 `easyADB.db` 能被读出设备列表

## P10 — Scrcpy 嵌入模式（可选增强，约 1.5 周）

> 仅在 MVP 稳定、用户明确反馈需要嵌入时实施。

### 难点
Compose Desktop 底层是 Swing，没有 Qt 那样的 `QWidget.createWindowContainer` 直接嵌入原生窗口的能力。

### 实现路线（Windows 优先）
- [ ] 引入 JNA（`net.java.dev.jna:jna`）
- [ ] `platform/windowsMain/.../Win32Interop.kt`：包装 `user32.FindWindow / SetParent / SetWindowLongPtr` 等
- [ ] `ui/mirror/.../EmbeddedScrcpyPanel.kt`：内部放一个 `SwingPanel(factory = { JPanel() })`，拿到 `hWnd` 后通过 JNA 把 scrcpy 的 SDL 窗口 reparent 进来
- [ ] 处理 DPI、缩放、焦点切换、键盘事件转发
- [ ] macOS / Linux 用各自 API（X11 / Cocoa），复杂度更高，可后续单独立项

### 验收标准
- 「嵌入模式」勾选后，scrcpy 窗口能塞进 Compose 应用内
- 鼠标点击/键盘输入能透传到 scrcpy

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| Compose Desktop 无原生 TreeView | 设备/命令树开发量增加 | 用递归 Composable 自实现，或评估第三方库（如 `compose-tree`） |
| 拖拽 API 缺失 | InstallApkDialog / ApkHelperDialog 受影响 | 走 Swing interop（`DropTarget`），P7 阶段先验证可行性 |
| Scrcpy 嵌入复杂 | P10 可能延期 | MVP 不做，独立窗口先满足需求 |
| Skia 在大日志量下卡顿 | Live Logcat 3000 条可能掉帧 | `LazyColumn` + 节流 + DiffUtil 思路；P6 提前做性能基准 |
| Kotlin 生态 ADB 库选择 | 自建 vs adblib | MVP 沿用「调 adb 二进制」路线，降低风险；P10 后再评估切 adblib |
| macOS 签名/公证 | 分发被阻 | P9 早期申请 Apple Developer ID，配置 `notarization` |
| 老数据库 schema 不兼容 | 用户数据丢失 | P1.3 强制保持表结构不变；P11 提供迁移工具 |

## 不在范围内（明确放弃）

- 移动端（Android / iOS）支持
- Scrcpy 嵌入模式的 macOS/Linux 实现（仅做 Windows，作为 P10 一部分）
- 多语言（i18n）—— MVP 仅中文
- 远程设备管理（云 adb）
- 自动更新（后续可接 `update4j` 或 `conveyor`）
