### 已知坑点（P1 及后续阶段注意）

- **expect/actual Beta**：Kotlin 2.0.21 中 `expect/actual class` 仍是 Beta，需加 `-Xexpect-actual-classes` 编译器标志

- **Kotlin 2.0+ Compose 插件**：必须同时 apply `org.jetbrains.compose` 和 `org.jetbrains.kotlin.plugin.compose` 两个插件
- **Gradle 9.0 兼容**：当前有 deprecated feature 警告，不影响构建，Gradle 9.0 需处理

### 关键设计决策

- **QThread → coroutine**：`LiveLogAdbThread` → `callbackFlow`，`DevicesWatcher` → `CoroutineScope` + `StateFlow`
- **pyqtSignal → Flow**：`changedSignal` → `devices: Flow<List<DeviceInfo>>`，`live_log_dump_signal` → `Flow<LogcatEntry>`
- **SQLite**：JDBC 直连（`org.xerial:sqlite-jdbc`），表结构与 Python 完全一致
- **INI 解析**：自写 `IniParser`（Java `Properties` 不支持 `[Section]`）
- **日志类型**：`LogLevel` 枚举替代 Python 的 `logging` 级别数字
- **仅 platform 模块使用 KMP**：EasyPyADB 目标单一（Windows 桌面工具），无需跨平台编译到 iOS/Android/Web。因此只将 `platform` 模块设为 `kotlin.multiplatform`（它需要 expect/actual 处理平台差异），其余所有模块（含 `desktop-app` 和 7 个 core 模块）保持 `kotlin("jvm")`，避免 KMP 带来的 expect/actual 声明、source set 层次结构等不必要的复杂度。

| 优化点 | 解决的问题 |
|---|---|
| 叶子节点用 `Modifier.clickable` 替代 `detectTapGestures(onTap, onDoubleTap)` | 消除 ~200ms doubleTapTimeout 等待 — **点击即时响应** |

### 新增坑点

- **`callbackFlow` 的 block 跑在收集方上下文**：在 block 里直接做阻塞 IO（readLine）会把收集方线程（通常是 Main）挂死；阻塞读必须显式 `launch(Dispatchers.IO)` + `awaitClose` 收尾销毁进程
- **SnapshotStateList 淘汰同步**：预算淘汰数可能越过旧条目、吃掉追加批里最老的部分，显示列表同步要先 `subList(0, dropOld).clear()` 再 `addAll(pending.subList(evicted - dropOld, size))`；若偷懒整表重建会退化成每 150ms 一次 O(N)
- **LazyColumn 内容 key**：append-only 日志列表里完全相同的行很常见，`pid + hashCode` 组合 key 必撞重复 key 崩溃；接入 seq 后用 `itemsIndexed(logEntries, key = { _, it -> it.seq })`——单调唯一，头部淘汰/尾部追加下 LazyColumn 精确增量更新
- **桌面 KeyEvent 的 key/type 是扩展属性**：`event.key` / `event.type` 在 desktop 上来自 `KeyEvent_desktopKt` 扩展，必须显式 `import androidx.compose.ui.input.key.key` / `androidx.compose.ui.input.key.type`；且 key 包与 pointer 包各有一个 `isCtrlPressed`（分别作用于 KeyEvent / PointerKeyboardModifiers），同名导入冲突，pointer 侧要用 import alias
- **桌面 SelectionContainer 自带右键菜单**：desktop 版内部经 foundation 的 `ContextMenuArea`（在 `androidx.compose.foundation` 包，**不在 ui 包**——按 ui 包搜会误判不存在）提供「复制/全选」默认项，会与自定义右键菜单叠加弹出；抑制法：`CompositionLocalProvider(LocalTextContextMenu provides 空实现)`（`androidx.compose.foundation.text`，实验性 API 需 `@OptIn(ExperimentalFoundationApi::class)`）。自定义右键菜单用 `onPointerEvent(Press) + isSecondaryPressed` 记录锚点 + `DropdownMenu(offset)`（设备树 TreeItem 同款，onPointerEvent 需 `ExperimentalComposeUiApi`）；选区文本无公开读取 API（无 LocalCopyManager），右键「复制」只能做全文（过滤视图）复制，选中复制仍走 Ctrl+C
- **桌面滚动条**：`androidx.compose.foundation.VerticalScrollbar` + `rememberScrollbarAdapter(LazyListState)`（都在 foundation 包，桌面专属），滑块拖动/轨道点击内建；需用 Box 包裹列表后 `align(Alignment.CenterEnd)` 叠放
- **指针事件的 Ctrl 判断**：Compose 1.7.3 的 `KeyboardModifierMasks` 是 file-private 不能位运算，key 包的 `isCtrlPressed` 只作用于 `KeyEvent`；滚轮事件要用 skiko 扩展 `androidx.compose.ui.input.pointer.isCtrlPressed`（`PointerEvent_skikoKt`，desktop 专属）

### 新增坑点
- **嵌入态下合成输入不可达**（KeySpike 设备侧断言：PostMessage/SendInput 在所有焦点配置下都送不进嵌入的 scrcpy，含「前台激活 + GetGUIThreadInfo 断言焦点已在子窗口」组合）；**键盘透传唯一可靠路径 = 焦点交付 + 真实键盘**（常驻 attach + 裸 SetFocus，用户实测可用）。曾误判为「scrcpy 2.3.1(SDL2) 死路、需 ≥3.x(SDL3)」——后核实本机 scrcpy-server（90980 字节，2026-02-27 起）从未更换，全部实验均在 3.3.4 上完成，无版本 A/B 依据，订正
- **`attach→SetFocus→detach` 是陷阱**：detach 拆散共享输入队列，子窗口拿不到焦点（`GetGUIThreadInfo` 断言实锤）；正确姿势 = 常驻 attach + 裸 SetFocus（对齐 Python `mousePressEvent` 的裸 `win32gui.SetFocus`）
- **`focusRequester.requestFocus()` 会把焦点抢回 Compose**，跟在 SetFocus(child) 之后等于亲手废掉键盘透传
- **SDL 初始化中途 reparent 触发 `0xC000041D`**（STATUS_FATAL_USER_CALLBACK_EXCEPTION，exitCode=-1073740771 秒退）——必须就绪门控（尺寸连续 2 拍 ≥50）后再收编
- CMP 1.7.3 的 `SwingPanel` 在 `androidx.compose.ui.awt` 包（不是 `uiinterop`/`interop`，两个都不对）
- JNA `HWND extends PointerType`：Long↔HWND 用 `Pointer(long)` 构造 + `Pointer.nativeValue()`，没有 `longValue()`；`AttachThreadInput` 参数要包 `DWORD`，`GetCurrentThreadId` 在 Kernel32 而 `GetWindowThreadProcessId` 在 User32；`SendInput` 三参签名返回 DWORD，`KEYEVENTF_*`/`INPUT_*` 常量在 `WinUser.KEYBDINPUT`/`WinUser.INPUT` 嵌套类上
- `GetAncestor(GA_PARENT)` 对顶层窗口返回**桌面窗口句柄**而非 null——「脱离成功」的断言要判「父 ≠ 宿主」
- 轻量 JPanel 的 `getComponentPointer` 会返回 null/上溯失败，嵌入宿主必须用重型 `java.awt.Canvas`
- KeySpike 断言技巧：`dumpsys input` RecentQueue 长度 10 会被设备侧输入挤压，基线计数法抖动大——用事件自带 `age=` 只认新鲜条目；SendInput 鼠标合成在 DPI 不感知 JVM 里坐标有偏差，只影响点击断言命中率

- `LogDirs`（新）：日志目录解析——系统属性 `easyadb.log.dir` 优先，缺省 **当前运行目录（user.dir）下的 logs**（统一对齐 Python 版 `BASE_PATH\logs` 约定，不用 LOCALAPPDATA；`Main.kt` 的显式设置同样指向工作目录 logs，打包 exe 后日志也在运行目录生成）
- `AppLogger`：`getLogger` 缺省走 `LogDirs.default()`；**同目录 handler 共享表**（`ConcurrentHashMap.computeIfAbsent`）；文件行带时间戳+级别+logger 名（`yyyy-MM-dd HH:mm:ss.SSS LEVEL [name] msg`，对齐 Python 版习惯）；退出时 `closeAll()`（`Main.kt` onCloseRequest 已接）
- `RollingFileHandler`：FileWriter → `OutputStreamWriter(UTF-8)`（原 FileWriter 用平台默认编码，中文 Windows 是 GBK）；roll 前先删目标（Windows renameTo 目标已存在直接失败，滚动链会从此断掉）
- `LogSelfCheck.kt`（新，`gradlew :core:log:run`）：真实落盘自检 9/9 PASS——默认目录解析、UTF-8 中文、多 logger 共目录共享写入、时间戳格式、大小滚动备份链、backupCount 约束；`core:log` 加 `runtimeOnly(slf4j-simple)`（kotlin-logging 运行时委托 SLF4J，自检独立运行需要，不影响下游）

**自检过程的坑**：断言字符串按"级别在前"写但实际格式是 `LEVEL [name] msg`（[名字] 在级别后），一度误判共享写入丢行——先反思断言再怀疑实现；`core:log` 独立运行报 `NoClassDefFoundError: org/slf4j/LoggerFactory` 即缺 slf4j 绑定。
