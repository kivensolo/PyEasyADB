### 已知坑点（P1 及后续阶段注意）

- **expect/actual Beta**：Kotlin 2.0.21 中 `expect/actual class` 仍是 Beta，需加 `-Xexpect-actual-classes` 编译器标志
- **日志初始化时序**：`System.setProperty` 必须在创建 logger **之前**调用，logger 必须是 `main()` 内的局部变量而非顶层变量

- **Kotlin 2.0+ Compose 插件**：必须同时 apply `org.jetbrains.compose` 和 `org.jetbrains.kotlin.plugin.compose` 两个插件
- **Gradle 9.0 兼容**：当前有 deprecated feature 警告，不影响构建，Gradle 9.0 需处理

### 关键设计决策

- **QThread → coroutine**：`LiveLogAdbThread` → `callbackFlow`，`DevicesWatcher` → `CoroutineScope` + `StateFlow`
- **pyqtSignal → Flow**：`changedSignal` → `devices: Flow<List<DeviceInfo>>`，`live_log_dump_signal` → `Flow<LogcatEntry>`
- **SQLite**：JDBC 直连（`org.xerial:sqlite-jdbc`），表结构与 Python 完全一致
- **INI 解析**：自写 `IniParser`（Java `Properties` 不支持 `[Section]`）
- **日志类型**：`LogLevel` 枚举替代 Python 的 `logging` 级别数字
- **仅 platform 模块使用 KMP**：EasyPyADB 目标单一（Windows 桌面工具），无需跨平台编译到 iOS/Android/Web。因此只将 `platform` 模块设为 `kotlin.multiplatform`（它需要 expect/actual 处理平台差异），其余所有模块（含 `desktop-app` 和 7 个 core 模块）保持 `kotlin("jvm")`，避免 KMP 带来的 expect/actual 声明、source set 层次结构等不必要的复杂度。

- **`detectTapGestures(onTap + onDoubleTap)` 必有 ~200ms 延迟**：内部需等待 doubleTapTimeout 区分单/双击；纯叶子节点应改用 `Modifier.clickable`
- **`rememberRipple` 已 deprecated**：Compose Multiplatform 1.7.3 中需用新 ripple API；如果项目 allWarningsAsErrors，需直接传 `indication = null`
- **`pointerInput(key)` 的 key 选择**：用 `node.id` 保证节点复用时手势识别重启；用 `Unit` 则不会重启（按需选择）
