# SP-2001 屏幕截图预览与保存

| 项 | 内容 |
|---|---|
| 领域 | 20 ADB 命令（快捷操作功能区） |
| 状态 | 已实施 |
| 日期 | 2026-10-21 |
| 关联 | H5 参照稿 `cmp/doc/ui-reference/index.html`（.modal-shotload / .modal-sspreview / .ss-* 系列） |

## 背景与决策

原 Compose 端 `m_screenshot` 点击后直接弹 AWT `FileDialog` 选路径，随后
`adb exec-out screencap -p > path`（`AdbExecutor.getScreenShoot`）落盘——无预览环节，
与 H5 参照稿的「Loading 弹窗 → 图片预览窗（刷新/旋转/复制/缩放/信息）→ 保存/取消」
三段式交互不一致。

决策：对齐 H5 交互重构为单 `DialogWindow` 状态机（Loading / Ready / Error 三态），
截图字节经内存直通预览与保存，不再二次走 adb。

## 链路

```
快捷操作「屏幕截图」(m_screenshot)
  → Main.kt onFunctionItemClick 拦截（设备未选中则控制台报错）
  → ScreenshotDialog 打开即捕获（Loading 页：文案 + 4%→86% 缓动进度条 + 取消）
  → AdbExecutor.captureScreenBytes：ProcessBuilder 直启 adb exec-out screencap -p，
    IO 线程读满 stdout 字节（不经 shell 重定向/文本解码，规避 PNG 二进制损坏与
    Windows CRLF 污染；20s 超时 destroyForcibly）
  → Ready 预览页：
      重新捕获   不关窗，视图区叠加 74% 深色遮罩 + spinner，完成后 zoom/rot 归位
      左旋/右旋  ±90° graphicsLayer.rotationZ，仅影响查看（文字按钮，不用图标——
                 旋转图标与刷新图标视觉相近易混淆）
      复制粘贴板 AWT Toolkit.systemClipboard + DataFlavor.imageFlavor
                 （Compose LocalClipboardManager 仅文本，位图必须走 AWT）
      缩放       ×1.25 步进 clamp 0.2–4；适应窗口 = zoom 归 1；
                 1:1 = 1/ContentScale.Fit 基准比例（clamp 0.2–8）；
                 放大超出视口出 5dp 滚动条 + 手型左键拖拽平移，小图居中
      信息行     实际分辨率 + 位色 + kB（等宽小字，如 1,920×1,080 PNG（24 位色）· 45.2 kB）
  → 保存：AWT FileDialog(SAVE) 选路径 → 内存 PNG 字节 writeBytes 落盘
          （原始 PNG，缩放/旋转不影响内容；不再 adb pull）
  → Error 页：获取失败文案 + 重试/关闭
```

## 实现详解

### 1. 窗口形态与状态机

单 `DialogWindow` + `rememberDialogState`（`resizable = true`），内容与尺寸都由
`ScreenshotUiState`（`sealed interface`：`Loading` / `Ready` / `Error`）驱动：

| 状态 | 窗口尺寸 | 内容 |
|---|---|---|
| Loading | 560×148 | 文案 + 取消 + 8dp 缓动进度条（H5 .modal-shotload 小窗） |
| Error | 460×190 | 错误文案 + 重试/关闭 |
| Ready | min(1150, 96% 屏宽) × min(780, 92% 屏高) | 预览完整布局（H5 .modal-sspreview） |

- **单窗口而非 H5 的双 modal**：H5 loading/preview 是两个弹层；Compose 端合并为一个
  DialogWindow 内切换内容，避免「关一窗开一窗」的闪烁与焦点跳动。尺寸经
  `LaunchedEffect(uiState)` 写 `dialogState.size`，随后 `dialogState.position =
  WindowPosition(Alignment.Center)` 重新居中（`WindowState` 的 size/position 均可写）。
- **尺寸换算口径**：`Toolkit.screenSize` 返回逻辑像素，与 dp 同尺度（沿用
  ApkHelperDialog 已验证的结论），可直接 `minOf(1150f, screen.width * 0.96f).dp`。
- **窗口图标**：`Icons.Filled.Android`（Material 机器人）染 Android 品牌绿 #3DDC84。
  `DialogWindow.icon` 收 `Painter`，而 `rememberVectorPainter(image)` 重载无 tint 参数，
  故经 `CanvasDrawScope().draw` 把 VectorPainter 画到 64px `ImageBitmap`
  （`ColorFilter.tint` 上色）后以 `BitmapPainter` 包装——不新增资源文件，明暗
  标题栏下均可见。

### 2. 预览页布局结构（Ready 态 Compose 树）

```
Column(fillMaxSize)
├─ 工具行 1  Row(padding 14/10, spacedBy 8)                     ── SsToolButton（按钮样式）
│    重新捕获(icon+文字, busy 时禁用) 左旋 90° 右旋 90° 复制到粘贴板
│    └─ 1dp Divider（行下分割线）
├─ 工具行 2  Row(padding 14/7)                                  ── SsBareToolButton（裸图标）
│    适应窗口 | 放大 | 缩小 | 1:1(等宽文字) + 46dp 百分比 + weight(1f) + 信息行(等宽 11.5sp)
├─ 视图区    Box(weight(1f), clip(RectangleShape), bg=ScreenshotViewBg, onSizeChanged)
│    ├─ 滚动层  Box(fillMaxSize, horizontalScroll + verticalScroll,
│    │            溢出时 pointerHoverIcon(Hand) + detectDragGestures→dispatchRawDelta)
│    │    └─ 互换盒 Box(size = max(视口, 旋转后内容), contentAlignment = Center)
│    │         └─ 载荷盒 Box(size = Fit×zoom 显示尺寸)
│    │              └─ Image(fillMaxSize, ContentScale.Fit, graphicsLayer { rotationZ })
│    ├─ 滚动条  HorizontalScrollbar / VerticalScrollbar（5dp，仅 maxValue > 0 时显示）
│    └─ 刷新遮罩 Box(ScreenshotReloadOverlay) + ScreenshotSpinner + 文案（busy 时）
└─ 底部      1dp Divider + Row(padding 14/10)
     ?(裸图标, 气泡向上) + weight(1f) + 保存(SsPrimaryButton 渐变) + 取消(SsPlainButton)
```

**分层意图：渲染与布局解耦。** 缩放/旋转全部由 `graphicsLayer`（绘制层变换）承担，
不参与布局测量——`Image` 的布局尺寸只由 Fit 基准 × zoom 显式算出交给外层盒子；
滚动范围由「互换盒 = max(视口, 旋转后内容)」显式控制，起点无负溢出。若让
graphicsLayer 的变换参与测量（如直接给 Image 加 size），Compose 并不感知绘制变换
后的视觉边界，滚动与居中都会失准——这正是「放大后盖住工具行」「小图靠左」两个
走查 bug 的共同根源（分别以 `clip` 裁剪与 max() 互换盒解决）。

**居中方案取舍**：小于视口时居中采用互换盒 `size = max(viewport, content)` +
`contentAlignment = Center`；`Modifier.wrapContentSize` 在 scroll 容器的无穷约束下
实测靠左，已弃用。

### 3. 图片数据流与缓存策略：内存直通，无磁盘缓存

```
adb exec-out stdout 字节（PNG，1080p 约 0.5–3MB）
  ├─ Ready.bytes  ：原始 PNG 字节（保存/剪贴板解码的数据源）
  └─ Ready.image  ：SkiaImage.makeFromEncoded(bytes).toComposeImageBitmap()
                    解码后 RGBA 位图（1920×1080×4 ≈ 7.9MB），预览渲染用
```

**只用内存，不落磁盘**，原因四点：

1. **会话级生命周期，零复用价值**：截图数据生命周期 = 弹窗生命周期，关窗即作废，
   不存在跨会话/跨功能复用场景——磁盘缓存命中率恒为零，写盘是纯开销。
2. **隐私**：截图内容是设备实时屏幕（可能含聊天、支付页面等敏感信息）。静默写盘
   等于替用户做了一次未授权的持久化。项目约定：截图只有在用户点「保存」并选择
   目录后才落盘。
3. **保存一致性**：`writeBytes(state.bytes)` 写的是 adb 捕获的原始 PNG，零二次
   编解码，与设备端 `screencap` 输出逐位一致；若有磁盘缓存层，就存在「保存了
   陈旧缓存图」的可能。
4. **实现最简**：单张约 10MB、弹窗会话级持有，无需 LRU/容量上限等淘汰策略。

**刷新（重新捕获）路径**：`startCapture` 取到新字节后整体替换 `Ready` 对象
（旧对象即刻不可达、可被 GC），同时 zoom/rot 归位——不增量更新字段，避免
「半新半旧」的中间态。

### 4. 内存占用与释放

- **量级**：一张 1080p 截图 ≈ PNG 字节 1–3MB + 解码位图 7.9MB，双份数据共约
  10MB，存活期 = 弹窗存活期。
- **释放走 Compose 状态生命周期 + GC，无显式释放代码**：
  - `uiState` 是弹窗 composable 内的 `remember { mutableStateOf(...) }`；`onDismiss`
    → DialogWindow 关闭 → 组合销毁 → remember 存储销毁 → `Ready` 引用断开；
  - `ByteArray` 由 JVM 堆 GC 回收；`ImageBitmap`（skiko Bitmap，像素在 native 内存）
    由 skiko 对象清理器在 GC 后回收——Compose Desktop 没有
    `ImageBitmap.close()` 这类显式释放 API，这是平台约束下的唯一路径；
  - 不做对象池/手动引用管理的理由：引用断开即「逻辑上已释放」，最终物理回收
    由运行时保证；单弹窗会话频率下即使 native 内存回收滞后一个 GC 周期也无害，
    而池化会引入生命周期耦合（复用到旧位图）与额外复杂度，收益为零。
- **Loading/Error 态取消**同路径且更轻：Loading 中关窗时字节尚未产出或已随失败
  分支丢弃，无可释放对象。

### 5. 协程与 adb 子进程生命周期

- 捕获运行在 `rememberCoroutineScope().launch` 中；**关窗 = 组合销毁 = scope 取消**，
  捕获协程随之取消，无泄漏句柄。
- adb 子进程：协程取消不会中断阻塞中的 `readBytes()`（它是非挂起的阻塞调用），
  正常场景 `screencap` 输出 EOF 后进程自然退出；极端场景（设备挂起）由
  `withTimeout(20s)` → `destroyForcibly()` 兜底杀进程，不会残留僵尸 adb。
- 超时与失败统一返回 `null` → 进入 Error 页，用户可重试。

### 6. 渲染与缩放数学

- Fit 基准：`fit = min(vpW/imgW, vpH/imgH)`（视口像素/图片像素，`onSizeChanged` 量取）；
- 显示尺寸 = `img × fit × zoom`；工具行步进 ×1.25，zoom 范围 0.2–4；
- **1:1**（像素对像素）= `1/fit`（clamp 0.2–8）——Fit 是基准 1，还原原始尺寸需
  放大 1/fit 倍；
- **±90° 旋转**：`quarter = (rot/90) % 2 != 0` 时互换盒宽高互换（绕中心旋转，
  视觉边界正好宽高对调），滚动与居中按旋转后的边界计算；
- 缩放/旋转均为查看态，`graphicsLayer` 变换不回写数据——保存与剪贴板始终输出
  原始字节。

## 关键取舍

- **二进制捕获不走 ExecUtils.execCmd**：其按 UTF-8 读文本会损坏 PNG；旧
  `getScreenShoot` 的 shell 重定向拿不到字节，两者均删除，统一 `captureScreenBytes`。
- **保存不二次 adb pull**：截图已在内存，FileDialog 确认后直接写盘，
  快且规避二次失败面。
- **新增 token**：`ScreenshotViewBg`（H5 .ss-view 暗 #0B1019 / 亮 #E8ECF2）、
  `ScreenshotReloadOverlay`（.ss-reload rgba(11,16,25,.74) 明暗同值）；
  工具按钮复用 MiniBtnBg/Border/Hover 体系，不重复造 token。

## 已知边界

- 截图超时固定 20s（对齐 execAdbCmd 全局超时）；慢设备大屏可能偶发超时，报错误页可重试。
- 复制到剪贴板依赖 AWT imageFlavor，个别不接受位图的粘贴目标表现为不可粘贴（与系统行为一致）。
- DialogWindow 使用系统原生标题栏（与项目其他弹窗一致），未复刻 H5 自绘标题栏。
- 位深解析走 AWT `ImageIO.read(...).colorModel.pixelSize`（skia 无对应 API），解码
  失败时置 0，信息行省略「（N 位色）」段。
