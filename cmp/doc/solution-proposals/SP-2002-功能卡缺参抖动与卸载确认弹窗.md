# SP-2002 功能卡缺参抖动与卸载确认弹窗

| 项 | 内容 |
|----|------|
| 领域 | 20 ADB 命令执行（功能区） |
| 状态 | 已实施 |
| 日期 | 2026-10-23 |
| 关联 | H5 参照稿 `cmp/doc/ui-reference/index.html`（@keyframes shake / .pfield.shake / #modalUninstall / .pick-chips / .btn-danger） |

## 1. 背景与目标

快捷操作功能卡点击后，若必填参数为空，此前仅有控制台文字提示（`CustomActionHandler` 的「[错误] 操作需要包名」），无视觉引导。H5 参照稿已演进：

1. **缺参抖动**：启动/停止/重启/清除数据/查询 CP 缺包名 → 包名输入框抖动；发送广播缺 Action → Action 输入框抖动（`@keyframes shake`：500ms ±5px 位移 + 红底 16%/7% 闪烁，红边保持 560ms，触发时聚焦输入框）。
2. **卸载确认弹窗**：卸载从「直接执行」改为确认弹窗（H5 `openUninstall`：预填参数区包名、第三方应用 chips 快速选择、「无法撤销」警示、红色危险按钮）。此前 CMP 端 `onUninstallConfirm` 恒返回 `true`，卸载无任何确认环节（与 Python 旧版/H5 均不一致，属迁移缺口）。

## 2. 决策

### 2.1 抖动效果：designsystem 通用能力（FieldShakeState）

`ui/designsystem/ShakeEffect.kt`：

- `FieldShakeState`：`trigger` 计数状态，`shake()` 自增即重放（等价 H5 remove/add `.shake` 类强制重启动画）。
- `FieldShakeState.observeFrame(focusRequester?)`：订阅并驱动动画，返回 `ShakeFrame(translationXPx, redOverlayAlpha, redEdge)`。关键帧逐拍复刻 H5（15/30/45/60/75/90% 时刻），红边窗口 560ms（动画 500ms + delay 60ms），触发瞬间聚焦输入框。

视觉消费在各输入框组件内自绘（位移 `graphicsLayer`、红叠底 `drawBehind` 叠 `AccentRed`、红边覆盖 focus 蓝）——先落地于 `AppParamPanel.CompactTextField` 与卸载弹窗 `PkgField`，两者输入框规格不同，按项目惯例不提取。

### 2.2 缺参判断：XML `requireParam` 配置驱动（本方案核心）

**不在代码里枚举 action 白名单**，而是给 `function_templates.xml` 新增属性：

```xml
<attr name="requireParam">pkg</attr>          <!-- 启动/停止/重启/卸载/清除数据 -->
<attr name="requireParam">action</attr>       <!-- 发送广播 -->
<attr name="requireParam">pkg,action</attr>   <!-- 多字段必填：逗号分隔，缺失字段全部抖动 -->
```

- `FunctionItem.requireParam: List<String>`（core，`XmlConfigLoader` 按逗号分隔解析，缺省空列表 = 无前置校验）。
- `Main.kt` 点击链路通用判断：设备已选（对齐 H5 `guard()` 顺序）前提下 `filter { paramShakeState.isMissing(it, state) }` 收集缺失字段 → 逐个抖动 + 控制台拼接提示（「请先填写包名、Action」），不进入执行链路。
- `ParamShakeState`（ui.functions）三方法按配置值分发：`isMissing(param, state)` 判空、`shake(param)` 触发、`paramLabel(param)` 文案短名。

**扩展方式**（新增必填字段，宿主点击链路零改动）：`AppParamState` 加字段 → `ParamShakeState` 加 `FieldShakeState` + 三方法各补一支 → `AppParamPanel` 对应输入框接 `shakeState.xxx`；XML 侧功能卡配 `requireParam` 即生效（多字段逗号分隔）。

**与 `isNeedPkgName` 的分工**：`requireParam` 管 UI 前置缺参反馈（抖动），`isNeedPkgName` 管执行层校验（`CustomActionHandler` 兜底）。发送广播 XML 同步改为 `isNeedPkgName=false`（广播由 Action 驱动、不强制包名，对齐 H5 口径），其 handler 硬编码排除随之删除，语义收归配置。仅改 CMP classpath 副本（`desktop-app/src/main/resources/config/`），仓库根 `res/config/` 为 Python 旧版默认内置配置不动。

### 2.3 卸载确认弹窗（UninstallConfirmDialog）

`ui/dialogs/UninstallConfirmDialog.kt`，挂载与结构同 SP-1001 NewConnectDialog（满窗 ModalScrim + 居中 440dp 卡片，主窗口内浮层非 OS 窗口）：

- 包名输入框预填参数区包名（打开瞬间快照），空包名点「卸载」→ 输入框抖动 + 聚焦（H5 为 focus+toast，CMP 统一抖动反馈）。
- chips 列第三方应用（`type != "系统"`，同 AppManagerPanel「第三方」口径），数据源为宿主 `appList`；打开时列表为空则顺带 `loadApps()`（StateFlow 更新弹窗内自动补齐）。chips 限高 148dp 滚动——真实设备应用数会撑爆 440dp 弹窗，超出 H5 演示稿的实用处理；流式换行用 `FlowRow`。
- 「无法撤销」警示 + 取消（btn-plain）/ 卸载（btn-danger 红渐变 #EF4444→#DC2626 + 红投影，hover 160ms 过渡提亮）。
- 拦截判据 `item.cmd.contains("uninstall")`（与 `CustomActionHandler.handleCmdItem` 既有判据同源）；确认后弹窗包名直接执行 `adb -s <ip> uninstall <pkg>`（不经 shell），**不回写参数区**（同 H5）。

新 token：`ChipBg/ChipBorder/ChipText/ChipHoverBg/ChipHoverText`（暗色取 H5 硬编码值，浅色推导）。
